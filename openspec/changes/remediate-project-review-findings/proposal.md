# Proposal

## Why

项目审查确认了多项跨越权限边界、订单可靠性、缓存一致性和 AI 输出安全的缺陷，其中部分可导致未授权写入、跨用户数据泄露、文件越界删除或秒杀订单丢失。现有单元测试虽全部通过，但主要覆盖正常路径和 Mock 交互，未验证真实组件语义与故障恢复，因此需要以可观察行为和故障场景为中心完成一轮系统性修复。

## What Changes

- 收紧上传、优惠券、商户和 Agent 会话的访问控制；删除路径必须限制在上传根目录并验证资源归属，业务写操作必须校验角色和资源所有权。
- **BREAKING**：移除通过 GET 删除上传文件的兼容接口；匿名或无权调用写接口将返回明确的 401/403 响应，而不再以业务成功或通用 HTTP 200 表示失败。
- 让登录验证码只能成功消费一次，并对验证码发送、校验失败及 Agent 调用实施服务端限流，敏感值不再写入日志。
- 重构秒杀受理、Kafka 消费、Outbox 补偿和 Redis 状态恢复，使“已受理”必然对应可恢复的订单意图，以数据库提交结果作为最终幂等依据，并提供可查询的订单处理状态。
- 修复逻辑过期缓存的数据 key/锁 key 冲突、空值穿透保护和事务后缓存失效；按表和事件类型修正 Canal 生命周期与失效逻辑，并保证新建活动立即进入准入索引。
- 强制 Agent 会话按用户隔离，使敏感确认可在多实例间安全完成，并在任何 SSE 内容发送前执行必要的输出校验和脱敏。
- 修复 RAG 分块结束条件，统一 BM25 与向量索引的文档身份，补齐 PGVector 运行依赖和启用条件，避免禁用向量检索时产生无效 embedding 调用。
- 使点赞、关注和 Feed 翻页在并发与同分值游标下保持幂等，减少附近商户和帖子列表的全表/N+1 查询。
- 建立版本化数据库迁移、环境化配置、统一请求校验与错误契约，并增加订单积压、缓存重建、RAG 降级和 LLM 超时等运行指标。
- 补充真实 Redis/MySQL/Kafka 边界的集成测试和故障注入测试，更新 README 中的测试数量、运行方式和降级语义。

## Capabilities

### New Capabilities

- `access-and-input-security`: 覆盖写接口授权、资源归属、上传文件边界、验证码一次性消费、限流、请求 DTO 校验和 HTTP 错误语义。
- `flash-deal-order-reliability`: 覆盖秒杀受理的可靠记录、Kafka 重试与提交、Outbox 生命周期、幂等落库、库存恢复和订单状态查询。
- `cache-and-index-coherence`: 覆盖逻辑过期缓存重建、防穿透、事务后失效、Canal 事件处理及活动准入索引同步。
- `agent-session-and-output-safety`: 覆盖会话所有权、并发更新、跨实例敏感确认、流式输出校验、脱敏和异步资源治理。
- `rag-retrieval-integrity`: 覆盖文档分块、混合检索身份融合、PGVector 启用/降级行为及检索结果元数据。
- `social-feed-consistency`: 覆盖点赞与关注幂等、计数一致性、Feed 游标稳定性及列表批量查询。
- `operational-readiness`: 覆盖数据库迁移、环境配置、可观测性、故障告警、集成测试和发布验证。

### Modified Capabilities

无。项目当前没有既有 OpenSpec capability，本变更为现有行为建立首批规格。

## Impact

- 受影响 API：`/upload/**`、优惠券与商户写接口、登录验证码接口、`/agent/**`、秒杀下单与订单状态查询，以及失败响应格式。
- 受影响模块：MVC 拦截与权限、用户服务、上传服务、秒杀 Lua/Redis/Kafka/Outbox、缓存与 Canal、Agent 会话和 SSE、RAG、社交 Feed、数据库 DDL 与配置。
- 数据与依赖：需要版本化迁移修复 Outbox 时间字段和唯一约束，补充 PostgreSQL JDBC 依赖；可能新增订单意图/消费状态记录、上传资源归属数据、Redis 会话与确认键。
- 运维影响：部署前需要执行数据库迁移；秒杀可靠性改造需分阶段启用并验证 Redis 状态恢复、Kafka 重投和积压告警；旧的 GET 文件删除调用方需要迁移到受保护的删除接口。
- 测试影响：保留现有单元测试，同时新增权限矩阵、真实 Redis 缓存语义、数据库事务、Kafka 重投/死信、进程中断恢复、SSE 事件顺序和 RAG 检索质量测试。
